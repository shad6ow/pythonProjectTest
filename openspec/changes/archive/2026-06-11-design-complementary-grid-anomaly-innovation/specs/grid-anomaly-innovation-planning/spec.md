## ADDED Requirements

### Requirement: Innovation relationship planning
The system SHALL document point A and point B as a complementary innovation pair for grid anomaly detection, where point A performs supervised fused anomaly detection and point B performs self-supervised normal usage pattern modeling.

#### Scenario: Point B addresses point A limitation
- **WHEN** the innovation plan describes point A as Transformer, random matrix theory, and decision-tree ensemble fusion
- **THEN** the plan MUST describe point B as solving point A limitations in unknown anomaly generalization, weak-label robustness, abnormal deviation feature generation, and abnormal period localization

#### Scenario: Avoid metric-only framing
- **WHEN** the innovation plan describes point B
- **THEN** the plan MUST present it as a normal-pattern modeling method rather than as a trusted score, review metric, or model-consistency post-processing step

#### Scenario: No unsupported claims
- **WHEN** the innovation plan mentions detection performance, Top-K hit rate, or experimental improvement
- **THEN** the plan MUST mark unverified values as pending validation unless they come from actual run logs, cross-validation results, or user-provided evidence

### Requirement: Supervised and self-supervised distinction
The system SHALL distinguish point A supervised discrimination from point B self-supervised normal pattern modeling.

#### Scenario: Point A role
- **WHEN** the plan describes point A
- **THEN** it MUST define point A as learning a supervised decision boundary or fused anomaly probability from labeled data

#### Scenario: Point B role
- **WHEN** the plan describes point B
- **THEN** it MUST define point B as learning normal electricity usage patterns from normal or low-risk users and producing abnormal deviation features

### Requirement: Source-grounded research synthesis
The system SHALL base the proposal on readable source materials, existing project code, and explicitly identified assumptions.

#### Scenario: Existing code alignment
- **WHEN** the plan proposes implementation work
- **THEN** the proposed work MUST align with available SGCC preprocessing, monthly sequence construction, random matrix theory features, Transformer features, and GBDT ensemble code paths

### Requirement: Verifiable experiment plan
The system SHALL define experiments that validate point B without inventing data.

#### Scenario: Experiment artifacts
- **WHEN** implementation tasks are generated
- **THEN** they MUST include steps to produce reproducible outputs such as self-supervised model logs, deviation feature files, abnormal-period files, ablation summaries, or run logs

#### Scenario: Separate evaluation objectives
- **WHEN** point B is evaluated
- **THEN** the evaluation MUST distinguish deviation-feature effectiveness, supervised-fusion improvement, weak-label robustness, and abnormal-period localization analysis
